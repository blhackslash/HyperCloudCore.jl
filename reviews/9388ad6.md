## Findings

### F1 (medium, CONFIRMED) — "nearest face" is the nearest face *plane*, measured from the inside too: ghosts outside one face get another face's tag
`src/Grid/Domains.jl:69-80` (and the claims at `:35` "the face nearest to it", `docs/src/particle_grids/domains.md:23`
"the tag of the nearest face").
`d_lo = abs(pos[d] - mins_f[d])` is also computed for axes on which the point is *inside* the box, so a ghost that is
outside only through the bottom face but close to the left face's plane gets the left tag:
- 2-D `[0,1]²`, h = 0.05, R = 2.5h: `(0.0, -0.15) → 1`, `(0.05, -0.15) → 1` (both only below the bottom wall);
  **66 of 276 ghosts** are outside on one axis only but tagged with the other (R = 5.5h: 206/616; jittered n = 50:
  39/704, e.g. `(-0.0365, 0.0009) → 3`, a ghost behind the left wall carrying the bottom tag).
- 3-D (new with this commit): unit cube n = 16, R = 2.5h: **2556 of the 5202 single-face ghosts** carry another
  face's tag (1404 of them away from the edge lines, e.g. `(0.0625, 0.0625, -0.1875) → 1`, a ghost under the z-min
  face tagged x-min); R = 5.5h: 7056/10404; n = 32: 5436/19602. In the thin anisotropic box of `probe_tags.jl` §4,
  857 of 1351.
The geometric nearest face of a point outside one face only is that face (the others are at
`sqrt(e² + d_inside²) > e`). The effect: with different conditions per face, a strip of about the band width along
every edge gets the neighbouring face's condition (e.g. an x-min inflow `FixedDirichlet` freezes the ghosts under the
y/z walls next to the inflow edge; Simulations' 2-D `Benchmarks2D/ShockVortex.jl:39` with Dirichlet/Outflow/`BenchWallY`
and `jet_common.jl` have this today). With the same condition on every face it is harmless except for F2.
This is the parent's 2-D rule, kept on purpose for bitwise-identical 2-D tags (verified, see Tests); the commit now
extends it to 3-D, where the mixed-face use case is new, and the docs describe a different rule.
- Fix (decision needed, changes 2-D tags): consider only the axes on which the point is outside
  (`pos[d] < mins[d]` or `> maxs[d]`) and take the smallest plane distance among those (first on ties). Points outside
  on one axis get that axis; edge/corner regions keep exactly the current tags, so only the ghosts counted above change.
  At the least, correct the docstring/docs to "the nearest face plane (also from the inside): ghosts within about the
  band width of an edge may carry the neighbouring face's tag".

### F2 (low, CONFIRMED) — in 3-D `Dict(t => OutflowBC() for t in 1:6)` is not the old `Dict(1 => OutflowBC())`
`docs/src/particle_grids/domains.md:31`, `src/Grid/Domains.jl:39-40` present the per-face map as the replacement of
the old tag-1 map. `OutflowBC` resolves one tag at a time, and ghosts of the other tags are status −1, i.e. never
donors (`src/Grid/BoundaryConditions.jl:101-103`); before, all 3-D ghosts were one tag and were resolved together.
Edge and corner ghosts therefore get different donors: `probe_outflow3d.jl`, unit cube with a smooth field:
86 of 2194 ghosts (n = 8, lattice), 207/4079 (n = 12, jitter 0.3), 91/8457 (R = 5.5h), 71/1666 (periodic z) differ,
by up to 0.32–0.90 on an O(1) field; no ghost is left orphaned. 1-D is unaffected (the walls are far apart); 2-D tags
are unchanged, so nothing changes there. No downstream 3-D box with a bc map exists today, so this only matters for new
3-D users and for the migration claim.
- Fix: either document that per-face outflow resolves edges from the face's own band (and is not bitwise the old
  single-tag result), or let `apply_boundary_conditions!` group tags that map to the same `OutflowBC` into one donor
  search (status 0 for every tag of the group), which reproduces the old 3-D result and makes F1 irrelevant for
  all-outflow boxes.

### F3 (low, CONFIRMED) — breaking change on a 0.7.x version line that HyperCloud's compat accepts
`Project.toml:3` is still `0.7.9`; HyperCloud.jl `Project.toml:18` has `HyperCloudCore = "0.7"` (`>= 0.7.0, < 0.8`).
The plan names "0.7.10 (or 0.8.0)". Released as 0.7.10, every 1-D/3-D map with only tag 1 silently (one `@warn`)
loses its condition on the right wall / other faces in downstream environments that update, e.g.
Simulations' `conservation_burgers.jl` (see Downstream) and `probe_tag2_run.jl`: the map `1 => OutflowBC()` goes from
max \|u\| 0.899 (transmitting) to 1.137 (right wall frozen). The behaviour change is only recorded in the docs (no
changelog in the repo).
- Fix: release as 0.8.0 (and bump HyperCloud's compat after updating its examples), or accept the 0.7.10 route
  explicitly in the release note; in either case put the migration line ("1-D/3-D: `Dict(1 => bc)` → `Dict(1 => bc,
  2 => bc)` / `1:6`") into the release notes.

### F4 (low, CONFIRMED) — no test where tag 2 changes a result
The new tests check the tags and the warnings only. Nothing applies a mixed 1-D map and checks the right wall: the
widened maps in `unit_core.jl:502`, `unit_schemes.jl:403/848/871`, `gpu_tests.jl:51` use the same condition on both
walls, so they would pass with either tagging. `probe_tag2_run.jl` shows the case that matters (Sod-tube map,
pulse at the right wall): branch 0.899 vs parent 1.137.
- Fix: in "Boundary conditions as kernels" (`test/unit_core.jl:498`), one `apply_boundary_conditions!` with
  `Dict(1 => FixedDirichlet(), 2 => OutflowBC())` on `x -> x`: left ghosts keep `pg.rhos`, right ghosts get the
  outermost interior value (`x_hi`). Cheap (no new type combination).

## Correctness checks that passed

- **2-D bitwise identical**: 0 mismatches over 734 385 grid particles (768 grids: jittered, anisotropic, periodic in
  x or y or both, offset domains, Float32) and 1.77 M random/tie/Inf points. The strict `<` loop in the order
  left, right, bottom, top is equivalent to `min` followed by the `==` cascade (first minimum wins), also when a
  periodic axis contributes `Inf` and for a fully periodic box (both return 1).
- **1-D** tag 1 iff `x < min`, 2 iff `x > max`; **3-D** 1..6 by the plane rule with the lower tag on ties at edges and
  corners; periodic axes never tagged; Float32 identical behaviour.
- **Ghosts of the narrow band, adaptivity, reordering, device grids**: tags are computed once in `get_points`; the
  reorder permutes them with the positions (`Reordering.jl:93`), compaction copies them (`Adaptivity.jl:666`),
  inserted particles are interior with tag 0 (`:677`), `_upload_particles!` and `device_grid` copy the array
  (`Adaptivity.jl:293`, `DeviceAdapt.jl:18`). Verified `tags[i] == get_tag(positions[i])` after construction,
  adaptivity events and reorder, and equal tags on `device_grid(Array, ·)`. The tag function is host-only (no kernel
  rules apply).
- **Spherical domain** unchanged (tag 1).
- **Warning**: `_check_bc_tags` now reports `[2]` uncovered for a 1-D `Dict(1 => bc)`, nothing for `1 => …, 2 => …`;
  once per (mapped, carried) per session, as before.

## Verdict

The change does what it claims: 2-D tags are bitwise identical to the parent on ~2.5 M checked points and grids
(jittered, anisotropic, mixed/fully periodic, offset, Float32), 1-D walls carry 1/2 and 3-D faces 1–6 with the lower
tag at edges and corners, periodic axes are skipped, tags survive reordering, adaptivity and the device copy, the
spherical domain is untouched, the warning reports the uncovered tag, and the new test fails on the parent. Full suite
1013/1013. Remaining: the "nearest face" rule is the nearest face plane measured from the inside too, so ghosts near an
edge carry the neighbouring face's tag (pre-existing in 2-D, now extended to 3-D, docs claim otherwise) (F1); per-face
outflow in 3-D differs from the old single-tag outflow at edges, contrary to the migration note (F2); the breaking
change needs 0.8.0 or an explicit decision since HyperCloud's compat `0.7` would pick up 0.7.10 (F3); and no test
observes tag 2 changing a result (F4). Downstream: two Simulations configs (`conservation_burgers.jl:22`,
`defect_setup.jl:47`) must switch to `Dict(1 => :outflow, 2 => :outflow)`; HyperCloud's Sod examples/test get the
right-wall outflow they always intended, with no change before t = 0.2.
Findings: 0 high, 1 medium (F1), 3 low (F2–F4); all confirmed.
