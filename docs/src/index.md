# HyperCloud: A Meshfree Hyperbolic Solver

HyperCloud provides a robust, meshfree computational framework for the numerical approximation of hyperbolic partial differential equations (PDEs). By rigorously decoupling the continuous geometric formulation from the discrete particle topology, the package facilitates arbitrary-order spatial approximations and stable temporal integration. 

The following documentation outlines the standard procedure for configuring the computational domain, spatial discretizations, and time-marching schemes required to execute a simulation.

## 1. Domain Generation and Particle Topology

The basis of the spatial discretization is the definition of the physical geometry, which delineates interior regions and boundaries.

* **Geometry Instantiation:** The physical bounds are established using the `GeometricDomain` structure. Standard primitive geometries can be instantiated via `get_rectangular_domain` or `get_spherical_domain`. These functions evaluate the bounding limits and assign numerical tags (e.g., 1 for left, 2 for right) to discrete boundary segments.

* **Grid Initialization:** The discrete computational topology is generated by passing the `GeometricDomain` to the `ParticleGrid` constructor. This requires specifying a nominal spatial resolution (`nominal_dx`) and a scaling parameter (`interp_range_factor`) to dictate the radius of the local neighbor search. The constructor automatically generates the point cloud, populates the continuous physics definition, and pre-allocates local neighbor lists.

## 2. Boundary Condition Formulation

Boundary constraints are directly mapped to the geometric boundary tags and evaluated systematically during the temporal integration sequence.

* **Available Conditions:** The package natively implements `FixedDirichlet` (which enforces a constant boundary state based on initial conditions) and `OutflowBC` (which extrapolates interior states to unresolved boundary particles to enforce zero-divergence).

* **Mapping:** Boundary conditions are configured by passing a dictionary (`bc_map`) of type `Dict{Int, AbstractBoundaryCondition}` into the geometric domain constructor. This maps the spatial tags to the corresponding boundary functors, ensuring they are executed at the conclusion of each Runge-Kutta stage.

## 3. Spatial Discretization and Interpolation

The evaluation of spatial derivatives relies on a generalized, high-order Moving Least Squares (MLS) interpolator.

* **Interpolator Configuration:** To compute the numerical divergence, an `UpwindDivergence` object is instantiated. This requires the spatial dimension, the state vector dimensionality (M), and the desired spatial order of accuracy.

* **Upwind Schemes:** The user must specify a numerical flux function (e.g., `UpwindFlux()`) and a designated scheme via the `algType` parameter. Supported algorithms include `ClassicAlgorithm` for generalized systems, as well as `TiwariAlgorithm` (for arbitrary dimensional scalar equations) and `PraveenAlgorithm` (for 2D scalar equations).

## 4. Temporal Integration

Time marching is governed by explicit or Implicit-Explicit (IMEX) Runge-Kutta formulations that orchestrate the spatial gradient evaluations and grid updates.

* **Tableau Selection:** Standard explicit methods (such as `RK1_Euler_Tableau`, `RK2_Ralston_Tableau`, `RK3_SSP_Tableau`, and `RK4_Classical_Tableau`) and IMEX frameworks (e.g., `IMEX_ARS233_Tableau`, `IMEX_SSP2332_Tableau`) are provided.

* **Stepper Initialization:** A time integration object, such as `GeneralRKTimeStepper` or `GeneralIMEXTimeStepper`, is constructed by passing the target PDE, the configured `DivergenceInterpolator`, and the selected Butcher tableau. This pre-allocates all necessary interaction buffers and intermediate stage memory.

## 5. Solver Execution

Advancing the simulation involves calculating the maximum stable step size and systematically executing the time integration object.

* **CFL Evaluation:** Prior to each step, a stable time increment `dt` is computed via `getTimeStep(particle_grid, pde, divergence_interpolator)`. This function evaluates an exact geometric Courant-Friedrichs-Lewy (CFL) condition, ensuring numerical stability across irregular meshfree topologies.

* **Integration Step:** The simulation is advanced by calling the time stepper functor: `time_stepper(pde, particle_grid, current_time, dt)`. This sequentially evaluates the Runge-Kutta stages, integrates any associated source terms or grid motions, and applies the boundary condition mappings to finalize the updated state.
